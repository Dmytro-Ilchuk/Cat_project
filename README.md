# NineLives

Студентська 2D гра про кота з дев’ятьма життями. Реалізовано рух, базовий бій і каркас дев’яти життів: екран результату, наступні спроби, завершення циклу та новий кіт. Прогрес поки лише в пам’яті; окремої сцени прихистку ще немає.

**Основна платформа — Web у браузері на комп’ютері. Керування — клавіатура та миша.** Геймпад, стіки й мобільне сенсорне керування поки поза поточним обсягом. Раніше створена Windows-збірка — допоміжна перевірка прототипу.

## Відкрити проєкт

1. Клонувати цей репозиторій через Git / GitHub Desktop.
2. У Unity Hub додати кореневу папку репозиторію. Назва папки `Cat_project` не заважає: назва продукту в Unity — `NineLives`.
3. Використовувати **Unity 6000.6.1f1**. Це погоджена версія всієї команди; попередню пропозицію 6.3 LTS скасовано. Не відкривати проєкт старішою версією.
4. Дочекатися імпорту пакетів. Для браузерної збірки встановити **Web Build Support** для цієї ж версії Unity. Web використовує IL2CPP та WebAssembly з інструментами модуля Web.
5. Відкрити `Assets/_Game/Scenes/Bootstrap.unity` і натиснути Play. У MainMenu вибрати «Грати». Меню працює мишею та через стрілки / Enter. У браузері кнопку «Вийти» приховано: вихід — закриття вкладки; в Editor кнопка зупиняє Play Mode.

## Основна збірка Web

У File → Build Profiles вибрати **Web Development**. Сцени: Bootstrap, MainMenu, PlatformTest. Збирати в `Builds/WebDevelopment` і запускати через **Build And Run** або локальний HTTP-сервер. `index.html` не відкривати через `file://`.

Для локального прототипу стиснення вимкнено: серверу не потрібні спеціальні заголовки стиснення. Перед публікацією окремо вибрати хостинг, увімкнути стиснення й перевірити завантаження та кешування. Наразі гра нікуди не опублікована.

У браузерному тесті перевіряти фокус після кліку по грі, паузу після переходу на іншу вкладку, **Esc / P**, читабельність при зміні розміру вікна та відсутність прокручування сторінки під час гри.

## Допоміжна збірка Windows

У File → Build Profiles вибрати **Windows Development**, натиснути Switch Profile, якщо профіль не активний. Development Build і Script Debugging увімкнені. Сцени: Bootstrap, MainMenu, PlatformTest.

Збирати в `Builds/WindowsDevelopment/NineLives.exe`. Передавати іншому учаснику **всю папку збірки**, включно з `NineLives_Data`, `UnityPlayer.dll` та рештою файлів. Unity Editor для запуску готової гри не потрібний.

Через підключений Unity CLI:

```powershell
unity command build --caller plugin --skill unity-cli --target StandaloneWindows64 --profileName "Windows Development" --outputPath Builds/WindowsDevelopment/NineLives.exe --options '["Development","AllowDebugging","DetailedBuildReport"]' --confirm true
unity command build_status --caller plugin --skill unity-cli
```

## Перевірити рух героя

Відкрити `Assets/_Game/Scenes/Tests/MovementTest.unity`, натиснути Play і клацнути у Game View. Рух ліворуч/праворуч: **A/D або стрілки**. Відпустити напрямок для гальмування. У сцені є шов між двома ділянками підлоги та стіни. Play запускає поточну відкриту сцену; для меню відкрити Bootstrap.

`Assets/_Game/Prefabs/Player.prefab` містить Rigidbody2D, CapsuleCollider2D, дочірній Visual і PlayerController. У компоненті налаштовуються Speed (6 одиниць/с), Acceleration (35) і Braking (50). Поворот змінює лише Visual. `IsGrounded` перевіряє контакти з Ground із нормальною вгору, тому бокова стіна не дає стану «на землі». Фізичний матеріал героя має нульове тертя.

Для автоматичної перевірки зі стандартними параметрами: у Play Mode цієї сцени вибрати **NineLives → Check Player Movement (Play Mode)** і не натискати кнопки приблизно 4 секунди. Очікується `PASS` у Console. Перевіряються розгін, швидкість, гальмування, зміна напрямку, поворот, шов, вимкнення Move і стіна. Тест використовує тимчасову віртуальну клавіатуру і відновлює позицію та налаштування після завершення.

MovementTest — коротка перевірка базового руху; запускається окремо в Editor і не входить до Windows Build Profile.

## Повна кімната етапу 2

Запуск: **Bootstrap → Грати**, або відкрити `Assets/_Game/Scenes/Tests/PlatformTest.unity` безпосередньо. Маршрут веде праворуч до жовтого прапорця: сходинки з підйомом 1,25 одиниці, верхній майданчик, ями завширшки 4 і 6 одиниць, прохід заввишки 1,25 одиниці. Широку яму долати стрибком і ривком біля вершини стрибка. Падіння нижче Y = −6 завдає 10 шкоди й повертає до початку.

| Механіка | Початкові параметри |
| --- | --- |
| Стрибок | Speed 11; раннє відпускання скорочує швидкість до 45%; висота приблизно 0,9–2 одиниці |
| Допуск після краю / буфер до землі | По 0,12 с |
| Ривок | Speed 16; тривалість 0,16 с; перезарядка 0,65 с від початку |
| Повітряний ривок | Один до приземлення; очікування перезарядки в повітрі не відновлює його |
| Фізика / камера | 60 Гц; Rigidbody2D Interpolate; стеження в LateUpdate з межами кімнати |
| Графіка | 16 PPU, 320×180, URP Pixel Perfect, Pixel Snapping, Windowbox; AA вимкнено |

Усі параметри руху доступні в PlayerController на prefab. Силует тимчасовий: Point, без mipmaps і стиснення. Один світовий блок відповідає 16 пікселям; фізичний габарит героя — 1,6×0,9 одиниці. На 1280×720 масштаб зображення 4×; інші пропорції додають поля без розтягування пікселів.

**Space** — стрибок, утримання дає більшу висоту; **Left Shift** — горизонтальний ривок у бік погляду. **Esc / P** відкриває й закриває паузу. Втрата фокусу також ставить гру на паузу. Меню дозволяє продовжити або припинити забіг із підтвердженням. Пауза зупиняє час, вимикає Gameplay і скасовує поточний ривок та буфер натискань. Після повернення для нового стрибка/ривка потрібно відпустити й натиснути кнопку заново.

Автоматична перевірка: у Play Mode кімнати вибрати **NineLives → Check Stage 2 (Play Mode)**. Приблизно 17 секунд не натискати кнопки. Очікується `PASS` у Console. Перевіряються стрибки, допуск, буфер, усі верхні платформи, широка яма, ривок та його відновлення, стіна, вузький прохід, пауза, повернення після падіння й камера. Перевірка працює зі стандартними параметрами prefab.

## Дев’ять життів — етап 4

Смерть списує рівно одне життя й відкриває екран результату. «Наступна спроба» відновлює кімнату, ворогів і HP, очищує корм і тимчасові дари; Спогади та список покращень кота залишаються. При 0 життів або перемозі доступний «Новий кіт»: 9 життів, без сили й валюти попереднього кота; дані профілю залишаються. Купівлю та застосування покращень реалізує наступний етап.

Пауза дозволяє продовжити або завершити забіг із підтвердженням і втратою одного життя. Головне меню доступне з екрана результату. Стару кнопку повернення на початок кімнати замінено завершенням забігу. Падіння тепер завдає 10 шкоди; смертельне падіння завершує спробу. Працюють атака кігтями (ЛКМ) і шипіння (Q).

У Play Mode PlatformTest: **NineLives → Stage 4 → Check full cycle (Play Mode)**. Перевірка змінює поточний тестовий цикл у пам’яті та закінчується в MainMenu; після неї зупинити Play Mode. Очікується `Stage 4 PASS`: дев’ять смертей, захист від повторного списання, нові спроби, скидання сили, збереження профілю, блокування мертвого героя, підтвердження припинення та рання перемога.

Тестова перемога: **NineLives → Stage 4 → Complete run as victory**. Там само є смертельна шкода й додавання Спогадів. Ці команди доступні лише в Editor. Збірку Web Development у `Builds/WebDevelopment` оновлено після візуальних змін.

## Візуал

Кіт і щури мають окремі атласи анімацій на основі `Visual Art References/New_Player_base.png` та `Rat_enemy_new_design.png`. Бій показує дуги кігтів, короткий спалах при уроні, частинки, шлейф ривка й розпад ворога; тряску камери можна вимкнути в головному меню. Меню використовує `Main Menu Final.png` як тло з анімованим дощем. `Main menu + buttons concept.png` задає розташування й верхні/нижні лінії кнопок.

Шрифти: **Press Start 2P** для великих заголовків, **Tiny5** для кнопок, HUD і тексту; обидва містять українську кирилицю. Файли та ліцензії OFL розміщено в `Assets/_Game/Art/Fonts`. Нові атласи створено вбудованим ImageGen за референсами: одна сітка кота 6×8 (спокій, крок, біг, стрибок, удар, ривок, біль, смерть) і одна сітка щура 6×4 (спокій, біг, атака, смерть), з прозорим тлом. Перевірка імпорту: **NineLives → Check Visuals**, очікується `Visuals PASS`.

## Перевірка

- Меню **NineLives → Validate Stage 1** перевіряє сцени, URP 2D, ввід, шари, матрицю зіткнень і кнопку виходу. Або `unity command eval 'NineLives.Editor.StageOneValidation.Validate();'`.
- Запустити Bootstrap в Editor: з’являється MainMenu без помилок у Console; «Вийти» завершує Play Mode.
- Запустити Windows-збірку й перевірити кнопку виходу.
- Учасник Б окремо перевіряє чистий clone та готову збірку на своєму ПК. Цю перевірку не замінює локальний тест.

## Структура та пакети

- `Assets/_Game/Scenes` — Bootstrap, MainMenu, Tests/MovementTest, Tests/PlatformTest.
- `Assets/_Game/Scripts` — ігровий код; початкові папки систем із плану.
- `Assets/_Game/Settings/NineLives.inputactions` — Gameplay/UI.
- `Assets/_Game/Editor` — перевірки етапів 1–2 та базового руху, не потрапляють у гру.
- `Assets/_Game/Art/Prototype`, `Prefabs/Player.prefab` — тимчасова графіка й герой; `Audio`, `Data` — майбутній контент.
- `Assets/Settings` — налаштування URP, 2D Renderer і Build Profile.
- `Docs` — дизайн і план розробки.

Точні версії зафіксовано в `Packages/manifest.json` та `Packages/packages-lock.json`: URP 17.6.0, Input System 1.20.0, uGUI 2.6.0, Test Framework 1.8.0, Pipeline 0.7.0-exp.1. Потрібні для етапу пакети вже встановлені. Нових залежностей не додано. Просте меню використовує uGUI Text зі штатним шрифтом; фінальне оформлення — пізніше.

У Renderer2D вимкнено **Post-processing → Enabled**, оскільки ефекти поки не використовуються. Увімкнути, коли з’явиться потреба в ефектах Volume. CLI працює з Editor; runtime Pipeline у готовій грі не налаштований. Єдине попередження збірки про відсутній RuntimePipelineConfig очікуване.

## Ввід

| Gameplay | Клавіатура / миша |
| --- | --- |
| Move | A/D / стрілки |
| Jump | Space |
| Attack | Ліва кнопка миші |
| Dash | Left Shift |
| Hiss | Q |
| Interact | E |
| Pause | Escape / P |

Працюють Move, Jump, Dash, Pause, Attack та Hiss (у PlatformTest). Interact підготовлено для наступних етапів. У меню Gameplay вимкнено. UI використовує окрему карту із шаблону Input System.

## Фізика 2D

Шари 8–13: Ground, Player, Enemy, PlayerHitbox, EnemyHitbox, Interactable. Увімкнені лише такі пари за участю цих шарів:

- Ground ↔ Player, Enemy.
- Player ↔ EnemyHitbox, Interactable.
- Enemy ↔ PlayerHitbox.

Player ↔ Enemy вимкнено: тіла не штовхають одне одного. Hitbox та Interactable надалі отримають trigger-колайдери; сама матриця шкоду не реалізує. Наявні стандартні шари між собою не змінено.

## Git

Зберігати `Assets` разом із `.meta`, `Packages`, `ProjectSettings`, `Docs` і README. Порожні початкові папки збережені в Git через `.gitkeep`. Ресурси переміщувати через Editor або разом із `.meta`.

Увімкнено Visible Meta Files і Force Text. `.gitignore` виключає Library, Temp, Logs, Obj, UserSettings, Build/Builds та згенеровані файли IDE. Збірки передавати окремо, не додавати в Git. Підключення GitHub-плагіна та авторизація локального Git — окремі способи доступу.
